# 개발 중 로컬 설치는 GitHub 등록을 로컬 디렉토리로 교체하는 swap 모델로 한다

> GitHub에서 설치한 `grimoire`가 이미 등록된 머신에서 로컬 체크아웃을 시험해야 하는 맥락에서, 같은 이름은 등록이 거부되거나 덮어써지고 다른 이름은 스킬과 훅이 이중으로 켜지는 문제에 직면하여, 우리는 마켓플레이스 이름을 `grimoire` 하나로 유지하고 등록 소스를 교체하는 swap 모델을 택하고 `grimoire-dev` 이중 이름, 별도 마켓플레이스 레포, `--plugin-dir` 동시 로드, 심볼릭 링크를 배제했다. 플러그인 ID(`archmage@grimoire`)를 전환 전후로 동일하게 유지하기 위해, 전환 시 Claude 쪽 플러그인 데이터가 삭제되는 비용과 Codex 캐시 재설치 절차를 감수한다.

## 맥락과 문제

Claude Code는 마켓플레이스를 이름당 하나만 등록하므로 로컬 디렉토리(`name: grimoire`) 추가가 거부되고, `--plugin-dir`은 설치본과 동시에 로드되어 스킬 중복과 훅 이중 실행이 생긴다. Codex는 `config.toml`의 `[marketplaces.grimoire]` 테이블이 로컬 소스로 덮어써지고 `plugins/cache`의 GitHub 사본과 어긋난다. `grimoire-dev` 같은 다른 이름으로 등록하면 `archmage@grimoire`와 `archmage@grimoire-dev`가 둘 다 활성된다. Claude에서 마켓플레이스를 제거하면 그 플러그인들의 데이터, 옵션, 시크릿이 함께 삭제된다. Codex는 플러그인을 캐시로 복사하므로 수정 반영에 재설치가 필요하다. 이 결정은 2026-10-20 별도 세션에서 검토되어 전달되었다.

## 고려한 선택지

1. swap 모델: 등록 상태를 읽어 출력하고, GitHub 등록이 있으면 제거 후 로컬로 교체(삭제되는 데이터를 명시하고 승인 후 실행), 끝나면 되돌린다.
2. `grimoire-dev` 이중 이름: 충돌은 없지만 스킬과 훅이 중복 활성된다.
3. 별도 마켓플레이스 레포(superpowers-marketplace 방식): 레포가 하나 늘고 로컬 시험 문제는 그대로다.
4. 하네스 캐시 디렉토리에 심볼릭 링크: Codex는 링크를 버리고, 캐시 구조는 비공개 구현이라 깨지기 쉽다.
5. 문서에 수동 절차만 기재: 구현 비용 0이지만 TOML 편집 실수가 잦고 기여자마다 환경이 달라진다.

## 결정

1번을 택한다. 구현은 `tools/grimoire.mjs`에 세 명령으로 들어간다.

- `dev-install`: 현재 등록 상태를 먼저 출력한다. GitHub 등록이 있으면 제거하고 로컬 디렉토리로 교체하되, Claude 쪽 데이터 삭제를 명시하고 승인을 받는다. 등록이 없으면 로컬만 추가한다. Codex는 소스 교체 후 설치된 플러그인마다 `codex plugin remove`와 `add`를 다시 수행한다.
- `dev-refresh`: 수정 반영용으로 Codex 재설치 절차를 반복한다.
- `dev-uninstall`: 로컬 등록을 제거하고 GitHub 소스로 되돌린다.
- 플러그인 ID는 전환 전후로 동일해 `enabledPlugins`를 건드리지 않는다. 이 불변식은 테스트로 둔다.

## 결과

- 좋음: 이름 하나, 설치본 하나. 사용자 설정 파일 변경이 코드로 고정되고 승인 절차를 거친다.
- 나쁨: 도구가 사용자 홈의 설정 파일을 다루므로 구현이 조심스럽다. 전환 시 Claude 플러그인 데이터가 삭제된다.
- 재검토 조건: Claude가 같은 이름의 마켓플레이스 소스 교체를 지원하거나 Codex가 로컬 마켓플레이스를 복사 없이 제자리에서 읽게 되면 단순화한다.
- 확인 수단: 구현 시 `tests/`에 상태 읽기와 ID 불변식 테스트를 추가한다. 구현 전까지 `docs/PLUGIN-AUTHORING.md`의 수동 절차가 대체 경로다. 구현 커밋에서 이 ADR을 `accepted`로 바꾼다.
