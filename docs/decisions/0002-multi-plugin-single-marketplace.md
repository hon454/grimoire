# 레포 하나에 여러 플러그인을 담고 마켓플레이스 `grimoire` 하나로 배포한다

> 스킬과 훅 모음을 Claude Code와 Codex에 배포하려는 맥락에서, 도메인별로 설치 단위를 나누면서도 관리는 한곳에서 하고 싶은 문제에 직면하여, 우리는 `plugins/` 아래 플러그인 여러 개와 마켓플레이스 하나를 택하고 레포 하나에 플러그인 하나(superpowers 방식)와 인큐베이터 플러그인을 배제했다. 사용자가 필요한 책만 설치하게 하기 위해, 플러그인마다 매니페스트와 버전을 따로 관리하는 비용을 감수한다.

## 맥락과 문제

레퍼런스 다섯 곳(superpowers, pstack-claude, ECC, mattpocock/skills, gstack)은 모두 레포 하나에 플러그인 하나다. grimoire는 "마도서 여러 권"이라는 컨셉상 도메인별 설치 단위가 필요하고, 두 하네스의 마켓플레이스 포맷은 모두 레포 안의 임의 경로를 플러그인 소스로 받는다.

## 고려한 선택지

1. 레포 하나에 플러그인 하나, 도메인은 스킬 폴더로만 구분: 설치가 한 번이지만 원치 않는 스킬까지 들어오고 훅이 전부 켜진다.
2. 레포 하나에 플러그인 여러 개, 마켓플레이스 하나: 책 단위 설치. 플러그인별 매니페스트와 버전 관리가 필요하다.
3. 플러그인마다 레포 분리: 마켓플레이스 레포가 따로 필요하고 공통 규약과 도구를 레포마다 복제해야 한다.

디렉토리 이름은 `books/`(컨셉 일치)와 `plugins/`(관례) 중 관례를 택했다. 메타 플러그인 이름은 `book-of-binding`, `archmage`, `book-of-the-archmage`, `primer` 중 `archmage`를 택했다. 인큐베이터 운영은 "스킬 3개 또는 전용 훅 발생 시 분리", "훅 필요 시에만 분리", "처음부터 분리", "규칙 없음" 중 "처음부터 분리"를 택했다.

## 결정

2번을 택한다.

- 플러그인은 `plugins/<name>/`에 두고, 이름은 kebab-case이며 `book-of-<domain>` 형식이다.
- 메타 플러그인은 `archmage`다. `book-of-*` 규칙의 유일한 예외로, 알파벳순 최상단에 와서 필독서로 눈에 띈다. 이전에 같은 이름의 메타 플러그인을 쓴 연속성도 있다.
- 인큐베이터는 두지 않는다. 메타 스킬이 아닌 모든 도메인은 첫 스킬부터 자기 책을 갖는다. 그래서 새 책 뼈대를 만드는 `new-book` 도구가 베이스라인 필수 요소가 됐다.
- 플러그인 간 의존은 금지한다. 두 하네스 모두 플러그인 루트 밖의 경로를 거부하고, Codex에는 의존성 선언이 없다.

## 결과

- 좋음: 사용자가 책을 골라 설치한다. 네임스페이스(`book-of-x:skill`)가 처음부터 고정되어 나중에 바뀌지 않는다.
- 나쁨: 스킬 1개짜리 책이 생길 수 있다. 플러그인마다 매니페스트 2장, `VERSION`, `CHANGELOG.md`를 관리해야 한다(이 비용은 [ADR 0005](0005-manifest-management.md)의 도구가 줄인다).
- 재검토 조건: Codex가 플러그인 의존성을 지원하게 되면 공용 스크립트를 담은 책을 분리하는 안을 검토한다.
- 확인 수단: `check`가 플러그인 이름 규칙과 `archmage` 예외를 검사하고, `new-book`이 `book-of-` 접두를 강제한다.
